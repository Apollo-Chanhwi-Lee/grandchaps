# 작곡메이트 (InstMate)

## 한 줄 소개

4~8마디 멜로디(악보 파일)를 붙이고 말로 요청하면, 그 멜로디를 후렴에 그대로 둔 2~4분짜리 밴드 곡 초안(악보, 파트별 MIDI, 미리듣기 음원)을 만들어 주는 작곡 도우미입니다. 밴드가 받아서 고치고 직접 연주하는 것이 목표이고, 음원은 미리듣기입니다.

## 실행 방법 (Apple Silicon Mac)

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.txt
brew install fluid-synth ffmpeg            # 음원 미리듣기 (없어도 악보와 MIDI는 동작)
INSTMATE_LEADSHEET_BASE=models/fused_sft1p7b \
INSTMATE_LEADSHEET_ADAPTER=models/leadsheet_dpo_v1_mlx \
.venv/bin/python app.py                    # http://127.0.0.1:8000
```

- 리드시트 모델(가중치)은 저장소에 없습니다. 위 두 경로에 두면 쓰고, 없으면 규칙만으로 곡을 만듭니다("내 멜로디 변형만").
- 대화 해석 모델(선택): `brew install ollama && ollama serve && ollama pull qwen3:14b`. 꺼져 있어도 대화는 규칙으로 동작합니다.
- 사운드폰트는 `models/soundfonts/`에 GeneralUser GS를 둡니다(`docs/LICENSES.md`).
- 테스트: `.venv/bin/python -m pytest -q`, 화면 상태 `node --test tests/test_stale_result.mjs`.
- 내 Mac에 한 번에 설치: `docs/설치_Mac.md` (`scripts/install_mac.py`, `start_mac.command`).
- Windows에서 이어 작업: `docs/윈도우_이어하기.md`. 공개 데모 페이지와 주소: `docs/공개배포_주소.md`.

## 구조

```
대화창(파일 + 글)
   │  POST /api/score/read, POST /api/chat
   ▼
대화 진행기 (instmate/chat.py)        순서는 코드가 고정: 악보 → 동의 → 장르 → 보컬 → 조성 되묻기
   │  말의 해석만 규칙 + qwen3:14b(선택)
   ▼
작곡 (instmate/composer.py)           규칙 초안 → 리드시트 모델이 벌스·프리·브릿지를 다시 씀 → 검사·재생성
   │  후렴 = 입력 멜로디 (바꾸지 않음, 매번 검사)
   ▼
편곡 (arrange.py, dynamics.py)        장르별 피아노·베이스·기타·드럼, 필인, 구간 흐름
   ▼
렌더 (audio.py)                       FluidSynth + 악기 표, 마스터, 선택 옵션(기본 꺼짐)
   ▼
가이드 보컬 (vocal.py)                 '아~' 합성 (옵션을 끄면 '라'/'나'). 별도 데모: YuE2 AI 보컬(선택)
```

기존 3단계 화면("직접 설정" 탭)은 그대로 있고, 마디별 코드 수정·파트 편집·밴드 팩 내보내기는 그쪽에 있습니다.

## 사용 모델과 데이터

| 구성 | 내용 | 근거 |
|---|---|---|
| 리드시트 모델 | Qwen3-1.7B + LoRA(MLX) + DPO, POP909 멜로디·코드로 학습 | `docs/training_log.md` |
| 코드 모델 | BiLSTM / HMM, POP909 마디별 코드 | `docs/architecture.md` |
| 대화 해석 | qwen3:14b (Apache-2.0, Ollama), 추가 학습 없음 | `docs/evaluation_agent.md` |
| 데이터 | 공개 데이터만: POP909(MIT)와 구조 레이블(MIT). 음원은 학습에 쓰지 않음 | `docs/LICENSES.md` |

상업 음원, 다른 생성 서비스의 출력은 학습·평가·비교 자료로 쓰지 않았습니다.

## 악기 라이선스 등급

악기는 `configs/instruments.yaml` 한 곳에서 관리하고 등급이 있습니다. **A**: 악기 자체를 앱과 함께 배포 가능. **B**: 그 악기로 만든 음원만 공유 가능(악기는 각자 설치). 화면의 "배포 모드"를 켜면 A 등급만 씁니다. Pedalboard·Surge XT·Dexed는 GPL-3.0이라 설치형 배포 전 검토가 필요합니다(`docs/LICENSES.md`).

## 한계와 향후 계획

- 모델은 장르를 구분하도록 학습되지 않았습니다(POP909에 장르 라벨 없음). 장르 차이는 규칙 편곡에서 나옵니다.
- 가이드 보컬은 음높이를 알려 주는 합성 목소리이고 가사가 없습니다. AI 보컬 데모는 입력 멜로디를 그대로 부르지 않습니다.
- 소리 옵션(믹스·마스터 2안, 보컬 다듬기, 구간별 강약, 자동 숨 자리, 끝 무음 자르기, 선율 다듬기)은 청음으로 확인된 것만 기본값을 켭니다.
- 청취 테스트(여러 사람)는 아직 하지 않았습니다. 자동 검사 통과는 음악성의 증거가 아닙니다.
- 향후: 탈락 후보 기록(브릿지 대체 원인 판별), 장르 라벨이 있는 공개 데이터 검토, YuE2-3B 라이선스·맥 구동은 확인 완료(10/5 사본 기준, `docs/LICENSES.md`).

# 상세판

아래는 구현 범위, 평가 수치, 폴더 구조를 담은 상세 문서입니다.

씨앗 멜로디(4~8마디)를 피아노롤이나 숫자 키로 입력하고 장르나 "희재 같은 느낌"을 말하면, 에이전트가 곡 구조를 설계하고 파트마다 멜로디와 코드를 만들고 스스로 검사해 고치면서 2~4분의 연주곡(악보, 재생, MIDI)을 완성하는 웹앱입니다. 리드시트는 직접 파인튜닝한 Qwen3-1.7B LoRA 모델이 쓰고, 코드 진행은 직접 학습한 BiLSTM이 고르며, 점수 계산과 음악 규칙 판정은 모두 코드가 합니다. 완성 뒤에는 "5~8마디를 더 어둡게, 템포 80" 같은 자연어 요청으로 다듬을 수 있습니다. 모든 모델은 맥북에서 로컬로 실행하며, 기본 구성은 외부 API를 쓰지 않습니다 (Gemini는 선택 경로). 범위는 밴드 편곡(피아노·베이스·드럼·기타, 선택: 스트링)이며, 가사와 노래 합성은 범위 밖이고 멜로디는 허밍 가이드 보컬(사용자 허밍의 음색 재합성)까지만 지원합니다. 발표용 실행은 `work/run_app.sh`(채택 모델 v1+DPO: `models/fused_sft1p7b` + `models/leadsheet_dpo_v1_mlx`)를 씁니다.

과제: AI응용특강 App 과제 (Category I). 제안서는 `docs/proposal_final.md`, 현재 통합 작업 지시서는 [`docs/1006_1차_지시서.md`](docs/1006_1차_지시서.md).

## 현재 구현 범위 (2026-10-06 기준)

**작곡메이트는 기존 작곡 모델과 장르별 편곡 규칙으로 밴드곡 초안을 만들고, 사용자가 브라우저에서 파트를 수정해 자기 버전과
합주 자료로 저장하는 도구다.** 아래 본문 중 이 절과 다른 설명은 이전 단계의 기록이며, 이 절이 우선한다.

| 무엇을 | 누가 만드나 | 근거 |
|---|---|---|
| 벌스·프리·브리지의 멜로디와 코드 | 작곡 모델(Qwen3-1.7B LoRA + DPO). POP909의 멜로디·코드로 학습. 끄고 규칙만 쓸 수 있다("내 멜로디 변형만") | `docs/training_log.md`, `docs/genre_data_audit_20261006.md` |
| 코드가 없는 악보의 코드 | 학습된 코드 모델(BiLSTM) 또는 규칙 | 화면에 "앱이 붙인 코드"로 표시 |
| 장르별 편성·리듬·기타 톤·구간 대비, **기타·베이스·드럼 파트** | **규칙.** 학습된 것이 아니다 | `instmate/genres.py`, `instmate/arrange.py`, `instmate/dynamics.py`, `configs/instruments.yaml` |
| 파트의 음 고치기, 밴드별 버전, 합주 자료 | 사용자 | 파트 편집기, 밴드 작업실, 밴드 팩 |

쓰지 않는 표현: "제이팝·감성록에 특화해 학습한 모델", "밴드 편곡을 딥러닝으로 생성", "발매에 자유롭게 사용 가능".

사용 흐름(화면은 한 단계씩 넘어간다): **1 멜로디·장르**(멜로디를 먼저: 내 악보 파일로 / 직접 입력 / 리드시트, 같은 화면
아래에서 장르·악기) → **2 만들기**(반주 또는 2~4분 곡 완성) → **3 듣고 고치기**(파트 편집, 밴드 버전 저장·비교, 밴드 팩).
곡 이름으로 스타일을 해석하는 입력과 레퍼런스 음원 올리기는 화면에서 뺐다(2026-10-06): 멜로디와 가사를 쓰지 않아 결과에
주는 것이 적었고 해석이 발라드로 쏠렸다. 서버의 해당 API(`/api/style`, `/api/reference`)는 남아 있으나 화면에서 부르지 않는다.
내 악보에서 시작하면 "AI 추천 코드로 3~4분 곡 완성"이 악보의 8마디를 멜로디 입력에 채우고, 고른 코드를 그 마디에 고정한 채
곡 완성까지 이어서 실행한다(그 8마디가 후렴이 된다).

입력 멜로디의 보존: 입력한 멜로디는 모든 후렴에 음높이·시작·길이 그대로 들어간다. 마지막 후렴을 반음 올리는 전조는 사용자가
켰을 때만 하고, 켜면 그 구간에 "(전조)"로 표시한다. 벌스·프리·브리지는 모델 또는 규칙이 새로 쓴다(입력을 후렴이 아닌 구간에
놓는 기능은 아직 없다). 악보 파일에 코드 기호가 있으면 그 코드를 그대로 쓰고 출처를 표시한다. 진단 기록:
`docs/melody_preservation_diagnosis_20261006.md`.

밴드별 방향: 밴드마다 분위기(자기 말로), 장르, 템포, 리드 보컬, 편성, 파트별 악기, 전조 여부를 따로 저장하고 원할 때 적용한다.
한 밴드의 설정이 다른 밴드나 앱 기본값을 바꾸지 않는다. 참고곡의 음원·악보는 받지 않는다.

선택 기능: 가이드 보컬(녹음한 목소리 또는 맥 음성으로 '나/라' 허밍), AI 보컬 데모(공개 모델 YuE2, 사전 생성 권장),
자연어 수정(Ollama), 악보 비교. 화면 라이브러리는 `static/vendor/`에 있어 외부 서버 없이 열린다.

검증 상태(2026-10-06 오후, 미커밋 포함 작업 트리, `.venv/bin/python -m pytest -q`와 `node --test tests/test_stale_result.mjs`):
자동 테스트 Python 1,220개 통과(1개 건너뜀)·화면 87개 통과. 실제 브라우저에서 악보 올리기, 곡 만들기, 베이스·기타·드럼 편집과 적용,
밴드 버전 저장·비교를 확인했다. **미검증:** 실제 목소리, 장르 적합성 청음, 실제 악기 연주, 실제 멤버의 MIDI
(`docs/user_acceptance_checklist.md`, 브라우저 확인 기록 `docs/browser_acceptance_20261006.md`). 평가 수치는 발라드 설정의 멜로디·코드에 대한 것이며 장르별 품질을 뜻하지 않는다.

다음 단계(제출 뒤, 실행 전 계획): 코드와 구간에서 파트별 연주를 배우는 실험을 베이스부터 (`docs/genre_training_plan.md`).

## 데모 흐름

`.venv/bin/python app.py`로 서버를 켜고 http://127.0.0.1:8000 을 엽니다.

1. **1. 멜로디 입력**: 피아노롤의 빈 칸을 클릭해 음을 넣고(끌면 길이, 음 클릭은 삭제), 숫자 키 1~7도 같이 쓸 수 있습니다. "예시 멜로디" 버튼으로 바로 시작할 수도 있습니다. 입력 아래에 악보가 실시간으로 그려집니다.
2. **2. 어떤 곡을 원하세요?**: 먼저 "성시경 희재 같은 느낌"을 쓰고 **스타일 해석**을 누르거나 **레퍼런스 음원 올리기**로 음원을 올리면(템포·조성·구조·에너지만 분석하고 파일은 바로 삭제) 장르·템포·악기·분위기 추천 카드와 한 줄 이유가 나옵니다. **추천대로 적용**을 눌러야 아래 설정이 채워지고, **다시**는 아무것도 바꾸지 않습니다. 설정(장르·악기·템포)은 추천 또는 직접 선택으로 정하며 출처 표시(추천/직접 입력)가 붙습니다. 스타일 단계를 건너뛰면 장르 기본값을 씁니다.
3. **곡 완성 (AI)** 를 누릅니다. 조성이 애매하면 되묻고, 그렇지 않으면 진행 목록에 도구 호출(구조 설계, 구간 생성, 점수 매기기, 렌더링)이 차례로 나타납니다.
4. **4. 곡 완성**: 구조 타임라인(파트마다 블록, 배지 `AI` / `규칙` / `씨앗`)이 나옵니다. **곡 재생**, **곡 MIDI 다운로드**, 악보를 볼 수 있고, 블록을 선택하면 그 파트만 재생됩니다. **이 파트 다시 만들기**로 한 파트만 다시 만들 수 있습니다(후렴은 씨앗이라 꺼짐). 곡과 파트마다 좋아요/별로를 남길 수 있습니다.
5. **반주 만들기**를 누르면 입력한 멜로디(4~8마디)의 반주가 만들어지고, 그 결과 화면의 **에이전트에게 요청** 칸에 "5~8마디를 더 어둡게, 템포 80"처럼 쓰면 에이전트가 도구를 호출해 그 마디만 고칩니다. 마디 범위 버튼, 템포·악기 세기, **이전 버전**(되돌리기)도 있습니다.
6. 화면 아래 **리드시트에서 곡 만들기**에 텍스트 리드시트(`docs/leadsheet_format.md`)를 붙여 넣어 곡을 만들 수도 있습니다.

## 에이전트 구조

에이전트 도구와 구현 위치입니다. 각 호출은 `{tool, input, output, ms}`로 trace에 남아 화면에 보입니다.

| 도구 | 하는 일 | 위치 |
|---|---|---|
| `analyze_melody` | 조성 분석 (Krumhansl-Kessler, 애매하면 되묻기) | `instmate/composer.py` (`theory.analyze_key` 호출) |
| `style_from_request` | 장르, 템포, 악기, 분위기로 해석 (LLM 또는 규칙), 코드가 다시 검증 | `composer.py`, `instmate/style.py` |
| `analyze_reference_audio` | 올린 음원의 템포·조성·구조·에너지 분석 후 삭제 | `instmate/refaudio.py` (`POST /api/reference`). 곡 생성 루프 안의 호출이 아니라 화면에서 실행하고, 확정된 스타일이 `compose`로 들어감 |
| `plan_structure` | 장르 템플릿을 템포에 맞춰 구조 설계 | `composer.py`, `instmate/song.py` |
| `generate_section` | 구간마다 후보 n개 생성 (Qwen3-1.7B LoRA, 학습과 같은 "채우기" 프롬프트) | `composer.py`, `instmate/lm_format.py` |
| `arrange_section` | 구간별 규칙 반주, 음역·마디 길이 검사 | `composer.py`, `instmate/arrange.py` |
| `score_section` | 후보 점수 (문법, 충돌률, 도약, 반복, 음역, 유사도 정책) | `composer.py`, `instmate/check.py`, `instmate/similarity.py` |
| `render` | 원래 조로 되돌려 MIDI·악보·재생 데이터 생성 (마지막 후렴 반음 올림) | `composer.py`, `instmate/render.py` |
| `explain` | 코드가 trace로 만든 한국어 요약 (LLM 없음) | `composer.py` |

**상태 기계 두 개.** `composer.py`는 곡 생성 루프입니다. 분석, 스타일, 구조, 규칙 초안, 그다음 구간마다 생성, 점수, 통과한 최고점 채택을 하고, 통과하지 못한 구간만 다음 회차로 넘깁니다(최대 3회차). 끝까지 실패하면 `fallback: rule`로 규칙 초안을 유지합니다. 후렴은 씨앗 멜로디 그대로라 다시 만들지 않습니다. `llm.py`는 자연어 수정 루프입니다. LLM이 `modify_bars`, `set_mix`, `ask_user`, `finish` 중 하나를 고르면 서버가 검증하고 작업용 사본에서 실행해 검사 결과를 돌려줍니다. 예산은 도구 호출 8회와 전체 60초(절대 마감 시간)이고, 마감은 성공 종료 경로(`finish`나 일반 텍스트 답)에서도 검사하며 HTTP 대기 시간도 남은 시간으로 줄입니다. 이미 실행 중인 도구를 중간에 끊지는 않고, 마감을 넘기면 그 결과를 채택하지 않을 뿐입니다. 실제 변경이 있을 때만 버전 하나로 채택합니다. LLM은 음을 만들지 않고 도구만 호출하며, 충돌 검사를 건너뛰는 인자(`allow_clash`)는 LLM 도구에 없습니다. 검사가 실패하면 요청은 아무것도 채택하지 않고 질문(`need_input`)으로 끝나며, 실패한 제안(`agent.pending`)을 사용자가 "그래도 적용" 버튼으로 확인해야만(`POST /api/agent/confirm`, 같은 버전·같은 마디·같은 방향에 묶임) 적용됩니다. LLM의 잘못된 형식의 출력(인자 자료형 오류 등)은 구조화된 거절로 돌려주고 채택하지 않습니다.

**곡 길이 계약.** 곡은 2~4분(120~240초)이어야 하며 `plan_structure`는 템포를 바꾸지 않고, 씨앗 후렴을 자르지 않고 이를 맞춥니다. 느린 템포에서는 파트를 줄이고, 그래도 길면 반복 파트(두 번째 벌스·프리, 가운데 후렴, 필요하면 브릿지)를 생략합니다(씨앗 후렴과 반음 올린 마지막 후렴은 유지). 씨앗 1~16마디, 장르 4종, 템포 40~200 전 조합에서 120~240초가 되는 것을 테스트로 확인했습니다(`tests/test_song.py`). 그래도 맞출 수 없는 경우를 대비해 `/api/song`과 곡 생성 결과는 `status: "duration_out_of_range"`, `duration_ok: false`, 한국어 설명 `duration_note`를 돌려주고 화면이 이를 표시합니다(성공 `ok`로 표시하지 않음). 사용자가 붙여 넣은 리드시트(`/api/leadsheet/render`)는 길이 요구가 없어 `status`는 `ok`이고 `duration_ok`/`duration_note`만 알려 줍니다.

**CrewAI/LangGraph를 쓰지 않은 이유.** 에이전트가 작은 명시적 상태 기계여서 모든 결정이 보이는 trace로 남고, 각 판단을 테스트할 수 있으며, LLM 없이도 돌기 때문입니다.

상세(점수식, 수정 루프의 잠금 검증, API 목록)는 `docs/architecture.md`에 있습니다.

## 실행 방법

```bash
uv venv --python 3.13 .venv            # 또는 python3 -m venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python app.py                # http://127.0.0.1:8000  (포트: INSTMATE_PORT)
```

Windows: `.venv\Scripts\python app.py`. 악보 표시(OpenSheetMusicDisplay 1.8.9)와 브라우저 재생(Tone.js 14.8.49)은 `static/vendor/`에 넣어 둔 파일을 쓰므로 인터넷 없이 화면이 열립니다.

**선택 구성 요소**

- **자연어 에이전트와 LLM 스타일 해석**: Ollama의 `qwen3:14b` (Apache-2.0). `brew install ollama`, `ollama serve`, `ollama pull qwen3:14b`. 모델은 `INSTMATE_OLLAMA_MODEL`로 바꿉니다. `INSTMATE_STYLE_LLM=off`는 스타일 해석을 항상 규칙으로 하고, `INSTMATE_LLM=gemini`와 `.env`의 `GEMINI_API_KEY`는 선택 경로입니다(무료 등급은 입력이 구글 제품 개선에 쓰일 수 있음).
- **리드시트 모델 (Qwen3-1.7B LoRA)**: Apple Silicon에서 `mlx-lm`으로 실행합니다. `requirements.txt`에는 들어 있지 않으므로 따로 설치해야 합니다. 어댑터는 `INSTMATE_LEADSHEET_ADAPTER`(기본 `models/leadsheet_lora_1p7b`, `adapters.safetensors`가 있을 때만), 기반 모델은 `INSTMATE_LEADSHEET_BASE`(기본 `Qwen/Qwen3-1.7B`, 로컬 캐시만 쓰고 내려받지 않음)입니다.
- **코드 모델 (BiLSTM, HMM)**: `models/`에 `chord_bilstm.pt`, `chord_hmm.npz`가 있으면 자동으로 쓰입니다. 다시 학습하려면 `scripts/train_chords.py`.
- **음원 렌더링 (M7)**: FluidSynth(`brew install fluid-synth`, Ubuntu `apt install fluidsynth`)와 무료 General MIDI 사운드폰트(GeneralUser GS 또는 FluidR3_GM, 라이선스는 `docs/LICENSES.md`)를 설치하면 "음원 다운로드" 버튼이 같은 MIDI(믹스 반영)를 CPU에서 WAV로 만들고, ffmpeg가 있으면 MP3로 줍니다. 사운드폰트 경로는 `INSTMATE_SOUNDFONT`(기본 `models/soundfonts/GeneralUser-GS.sf2`, 그다음 `FluidR3_GM.sf2`), 실행 파일은 `INSTMATE_FLUIDSYNTH`/`INSTMATE_FFMPEG`로 바꿀 수 있습니다. 상태 확인은 `GET /api/audio/status`.
- 데이터 저장 위치는 `INSTMATE_DATA` (기본 `data/`, 사용자 선택 기억과 곡 기록의 SQLite).

**LLM이나 모델이 없을 때 동작하는 것**

| 없는 것 | 그래도 되는 것 | 안 되는 것 |
|---|---|---|
| Ollama (LLM) | 입력, 조성 분석, 코드 생성, 편곡, 마디·범위 버튼 수정, 템포·세기, 스타일 해석(규칙), 레퍼런스 분석, 곡 완성 | 자연어 에이전트 요청 (`/api/agent`는 503) |
| 리드시트 어댑터 또는 `mlx_lm` | 곡 완성 (모든 구간을 규칙 기반으로 만들고 안내 문장에 밝힘) | 모델이 쓰는 구간 (`AI` 배지) |
| 코드 모델 파일 | 규칙 기반 코드 엔진 | BiLSTM 코드 |
| FluidSynth 또는 사운드폰트 | 브라우저 재생, MIDI 다운로드 | 음원 다운로드 (`/api/audio`는 이유와 함께 503) |
| ffmpeg | WAV 음원 다운로드 | MP3 (자동으로 WAV를 줌) |

## 결과

세 종류를 섞어 읽으면 안 됩니다. **테스트 세트**는 모델과 정책을 확정한 뒤 한 번 잰 최종 수치입니다. **검증 세트**는 모델을 고르는 데 쓴 개발용 수치입니다(여기서는 학습 기록의 것만 인용). **held-out**은 에이전트 평가에서 수정 전에 따로 써 두고 한 번만 실행한 요청입니다. 괄호는 곡 단위 부트스트랩 95% 신뢰구간(재표본 2000회, 시드 42)입니다.

### 4. 자연어 에이전트, qwen3:14b, 요청당 1회 (`docs/evaluation_agent.md`)

| 측정 | n | 도구 호출 정확도 | 결과 정확도 | 잠금 위반 | 평균 지연 |
|---|---|---|---|---|---|
| v1 (수정 전) | 20 | 14/20 (70%) | 10/20 (50%) | 0 | 10.0초 |
| v2 (수정 후, 같은 20개, **개발 숫자**) | 20 | 20/20 (100%) | 18/20 (90%) | 0 | 8.1초 |
| held-out (수정 후, 새 10개, **더 공정한 추정**) | 10 | 10/10 (100%) | 8/10 (80%) | 1 | 8.0초 |

v2는 v1의 실패를 보고 고친 뒤 같은 20개로 다시 잰 것이라 일반 성능이 아닙니다. held-out은 표본이 10개라 한 요청이 10%p이고 신뢰구간이 넓습니다. 남은 실패는 요청의 범위를 잘못 옮기거나 요청하지 않은 마디를 바꾸는 종류입니다.

## 한계

- **멜로디 데이터가 보컬 선이다.** POP909의 멜로디 트랙은 보컬 라인이라 인트로·간주·아웃트로에는 음표가 거의 없고, 그래서 모델이 쓰는 이 구간들은 성깁니다. 이 구간은 음표 수 검사를 빼고 코드 중심으로 점수를 매깁니다.
- **구간 이름은 휴리스틱이다.** 구조 레이블(사람이 붙인 A, B 같은 글자)에서 벌스·프리·후렴·브릿지를 규칙으로 추정했으며 정답이 아닙니다.
- **장르 태그가 학습에서 상수다.** POP909에는 장르 라벨이 없어 모든 학습 샘플의 헤더가 `[장르:발라드]`입니다. 모델은 장르를 구분하도록 학습되지 않았고, 장르 차이는 규칙 반주 쪽에서 나옵니다.
- **지시서의 8음 유사도 규칙은 실제 곡도 전부 표시한다.** 검증 세트 원곡 71곡이 학습 곡과 모두 8음 이상 일치하고 (`runs/similarity_index.json`), 테스트 세트 원곡 기준선도 100.0%입니다. 그래서 음높이+리듬 색인과 연속 10음 임계값의 보정된 정책을 쓰며(검증 세트 표시 비율 0.070423, 기준 0.1 이하), 이 정책의 테스트 세트 원곡 기준선 표시 비율은 6.9%입니다. 저작권 침해가 없다는 보증이 아니라 "학습 곡과의 긴 일치를 막는 검사"입니다.
- **에이전트의 범위 실수.** held-out 10개 중 2개가 실패했고 그중 하나(H1, "2마디를 조금 어둡게")는 모델이 요청하지 않은 5마디까지 바꿔 잠금 위반이 1건 나왔습니다. 요청 범위를 잘못 옮기는 문제는 고치지 않았습니다. 코드가 만드는 "실제 변경" 줄은 항상 사실이라 사용자는 그 줄을 기준으로 읽어야 합니다.
- **평가 설정의 한계.** 씨앗이 원곡 후렴이라 후렴 멜로디는 원곡과 같습니다. 곡 생성 평가의 충돌률 차이는 코드 선택과 나머지 구간에서 옵니다.
- **청취 테스트 미실시.** 음악적 완성도는 사람이 듣고 평가하기 전까지 검증되지 않았습니다.
- **음원 렌더링은 FluidSynth 오프라인 렌더링만.** M7의 FluidSynth 렌더링(`instmate/audio.py`, `POST /api/audio`, 화면의 "음원 다운로드")은 있지만 FluidSynth와 사운드폰트를 따로 설치해야 하고(`INSTMATE_SOUNDFONT`, docs/LICENSES.md), 없으면 이유를 알려 주고 MIDI·브라우저 재생만 됩니다. MRT2(선택), Qwen3 4B, AMT 반주는 하지 않았습니다.
- **보컬과 가사 없음.** 결과물은 연주곡입니다.
- 모델이 쓴 파트는 자기 코드를 그대로 유지하므로, 확정한 스타일의 밝은/어두운 코드 쏠림은 규칙 초안 쪽에만 반영됩니다.
- LoRA 체크포인트는 결과를 본 뒤 골랐습니다 (검증 세트 기준, 테스트 세트는 사용 안 함).

## 테스트 실행

```bash
.venv/bin/python -m pytest -q          # Python 테스트
node --check static/app.js             # 화면 스크립트 문법
node --test tests/test_stale_result.mjs    # 화면 경합 테스트
```

실행 중인 앱(포트 8000, `data/prefs.db`)에 테스트 요청을 보내지 마세요. 수정 요청이 취향을 기록합니다. 따로 확인하려면 `INSTMATE_DATA=<임시 폴더> INSTMATE_PORT=8001 .venv/bin/python app.py`로 격리된 서버를 띄웁니다.
최종 평가 스크립트 `scripts/eval_final.py`의 테스트 세트 실행은 이미 끝났고 결과 문서는 실행할 때마다 다시 만들어지므로, 테스트 세트로 다시 돌리지 않습니다.

## 악기 라이선스 등급과 배포 모드

- 악기는 전부 `configs/instruments.yaml` 한 파일에서 관리한다. 악기마다 라이선스 등급(`tier`)이 있다: **A**는 악기 자체를 앱과 함께 배포할 수 있고, **B**는 그 악기로 만든 음원만 나눌 수 있다 (악기는 각자 설치).
- 1단계 "파트별 악기·장비 고르기"의 **배포 모드** 스위치를 켜면 A 등급만 쓴다. B 악기(예: Vital 패드)는 A 악기(Surge XT 패드)로 자동으로 바뀌고, 무엇이 바뀌었는지 음원을 만들 때 화면에 나온다. 서버 기본값은 `INSTMATE_MODE=release`로 바꿀 수 있다.
- 플러그인·샘플은 사용자가 직접 설치한다. 앱은 설치 여부만 확인하고, 없으면 GeneralUser GS 사운드폰트로 대체한다. 실행 중에 악기 소리를 인터넷에서 받지 않는다.
- Surge XT 패드 소리: `.venv/bin/python scripts/make_surge_pad.py` (`models/`는 저장소에 올리지 않으므로 새 컴퓨터에서는 한 번 실행한다. 없으면 사운드폰트 현악으로 대체된다).
- VSCO-2 현악 합주(CC0, 발라드·J-pop 스트링): 샘플 받는 명령은 `scripts/make_vsco_strings.py` 맨 위에 있고, 받은 뒤 그 스크립트를 한 번 실행한다 (`sfizz_render` 필요). 없으면 사운드폰트 현악으로 대체된다.
- 기타 앰프 플러그인(Neural Amp Modeler): 설치만으로는 소리가 바뀌지 않는다. `scripts/vst_pick.py --fx crunch` (또는 `distortion`)로 창을 열어 캡처를 고르고 닫으면 저장된다. 캡처 파일의 라이선스를 `docs/LICENSES.md`에 적기 전에는 데모 모드에서만 쓰인다.
- 배포 모드는 보컬에도 적용된다: 맥 시스템 음성 대신 내장 합성 음성을 쓰고, AI 보컬 데모(YuE2)는 쓰지 않는다.
- **GPL 주의**: Pedalboard, Surge XT, Dexed는 GPL-3.0이다. 웹 서비스로 제공할 때는 소스 공개 의무가 없지만, 설치형 앱으로 배포하려면 앱 전체의 GPL 적용 여부를 먼저 검토해야 한다. 상세와 악기별 상태는 `docs/LICENSES.md`.
